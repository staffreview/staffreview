title: The docs
description: Capture a project-specific gotcha once, and every future review checks for it automatically.
---

The **docs** (`.staffreview/docs/`) is your team’s captured review wisdom.
Each entry is a Markdown file describing a mistake worth never repeating —
context, the issue, the original and fixed code, and why it matters.

## How entries get created

1. In the web UI, flag a comment with **Document**. This sets
   `documentRequested: true` on the thread but leaves it open — it’s a request,
   not a resolution.
2. Run `/staff-resolve`. The agent writes the lesson up as a new file under
   `.staffreview/docs/` and resolves the thread as `documented`.

You can also seed the docs from an existing GitHub PR review comment with
[`/staff-document`](/docs/skills).

## How the docs is used

`/staff-review` reads the docs on **every** pass. After its from-scratch
review, it walks the docs one entry at a time and re-flags any recurrence of
a documented mistake in the current diff — citing the entry it came from. This
is what catches the issues a from-scratch pass misses.

<Callout title="Commit the docs">
  `.staffreview/docs/` is meant to be **committed** so the whole team shares
  one memory. The session data — `.staffreview/diffs/`, `attachments/`, and
  `active.json` — is gitignored automatically by `staff install`.
</Callout>

## Build it early

The first time *anyone* — a human or an agent — flags something
project-specific, click **Document** and let `/staff-resolve` write it up. From
then on it’s checked on every review.
